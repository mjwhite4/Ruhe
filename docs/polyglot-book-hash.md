
## Polyglot Book Hash

To build a **PolyGlot-compatible opening book (`.bin`)** generator, you must use **PolyGlot’s specific Zobrist Hashing scheme**, which is distinct from standard engine transposition tables.

PolyGlot was created by **Fabien Letouzey** (the author of Fruit), and its hashing implementation relies on a specific PRNG algorithm and deterministic initialization rules to construct an array of 781 pseudo-random 64-bit numbers.

---

### 1. How PolyGlot Generates Random Numbers

PolyGlot generates its 781 Zobrist keys using a custom pseudo-random number generator function (often named `Random64`).

The PRNG uses a linear congruential / bit-shift method initialized with the fixed seed **`0x123456789ABCDEF1`** (or decimal `1311768467294899697`):

```c
// PolyGlot PRNG (pseudo-code implementation in C)
uint64_t seed = 0x123456789ABCDEF1ULL;

uint64_t polyglot_random64() {
    seed = seed * 2862933555777941757ULL + 3037000493ULL;
    return seed;
}

```

By calling this function sequentially 781 times, PolyGlot fills a static array of keys (`PolyglotRandom[781]`) representing all possible board states.

---

### 2. Layout of the 781 Zobrist Keys Array

The 781 values generated by the PRNG mapped directly to game components in the following strict order:

| Index Range | Offset Size | Represents |
| --- | --- | --- |
| **0 – 767** | $12 \times 64 = 768$ | **Pieces on Squares**: 12 piece types (White Pawn to Black King) $\times$ 64 squares |
| **768 – 771** | 4 | **Castling Rights**: White Short, White Long, Black Short, Black Long |
| **772 – 779** | 8 | **En Passant Files**: Files `A` through `H` (if en passant is legal) |
| **780** | 1 | **Side to Move**: XOR'd if it is **White's** turn to move |

#### Special Mapping Rules:

1. **Piece Mapping Index Formula:**

$$\text{Index} = (64 \times \text{PieceType}) + \text{SquareIndex}$$


* Piece Types (0 to 11): `0: BPawn`, `1: WPawn`, `2: BKnight`, `3: WKnight`, `4: BBishop`, `5: WBishop`, `6: BRook`, `7: WRook`, `8: BQueen`, `9: WQueen`, `10: BKing`, `11: WKing`.
* Square Index (0 to 63): $0 = \text{A1}, 1 = \text{B1}, \dots, 63 = \text{H8}$.


2. **Castling Index Formula:**
* White Short (`K`): Index `768`
* White Long (`Q`): Index `769`
* Black Short (`k`): Index `770`
* Black Long (`q`): Index `771`


3. **En Passant Index Formula:**
* Has a value **only if a pawn capture is legally possible** on the target square.
* File $A$ (0) to File $H$ (7): Index `772 + file`


4. **Side to Move:**
* PolyGlot XORs index `780` **only if White is to move** (unlike many chess engines which XOR when Black is to move).



---

### 3. Calculating the Hash for a Position

To compute the PolyGlot key for a board:

```python
polyglot_key = 0

# 1. Pieces on Board
for square, piece in board.items():
    polyglot_key ^= PolyglotRandom[64 * piece.type + square]

# 2. Castling Rights
if board.can_castle_white_kingside():  polyglot_key ^= PolyglotRandom[768]
if board.can_castle_white_queenside(): polyglot_key ^= PolyglotRandom[769]
if board.can_castle_black_kingside():  polyglot_key ^= PolyglotRandom[770]
if board.can_castle_black_queenside(): polyglot_key ^= PolyglotRandom[771]

# 3. En Passant (Only if a legal pawn capture exists!)
if board.has_legal_en_passant():
    polyglot_key ^= PolyglotRandom[772 + ep_file]

# 4. Turn (If White to move)
if board.turn == WHITE:
    polyglot_key ^= PolyglotRandom[780]

```

### 4. Binary File Structure (`.bin` Format)

Once you have computed the hash key, each entry in the `.bin` book is written as a fixed **16-byte record** formatted in **Big-Endian**:

| Field | Size | Type | Description |
| --- | --- | --- | --- |
| **Key** | 8 bytes | `uint64_t` | The 64-bit PolyGlot Zobrist key. |
| **Move** | 2 bytes | `uint16_t` | Compressed move representation (From, To, Promotion). |
| **Weight** | 2 bytes | `uint16_t` | Priority/frequency of the move (higher = preferred). |
| **Learn** | 4 bytes | `uint32_t` | Reserved for engine learning/stats (usually set to `0`). |

#### Move Format Encoding (16-bit):

* **Bits 0–2:** Promotion piece (0: None, 1: Knight, 2: Bishop, 3: Rook, 4: Queen).
* **Bits 3–8:** Target square (`0` to `63`).
* **Bits 9–14:** From square (`0` to `63`).
* **Bit 15:** Unused (`0`).

*Note for Castling Moves:* In PolyGlot `.bin` files, King moves during castling are encoded as **King moves to the Rook's square** (e.g., White short castling $E1 \to G1$ is recorded as $E1 \to H1$).
